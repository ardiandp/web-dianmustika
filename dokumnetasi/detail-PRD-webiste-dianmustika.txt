PRD Dian Mustika — Bagian 1: Product Definition
1.1 Product Name

Dian Mustika — Official Website

Website resmi untuk memperkenalkan brand Dian Mustika, layanan perawatan, lokasi layanan, promo, serta mengarahkan calon pelanggan untuk melakukan konsultasi melalui WhatsApp.

1.2 Product Type

Company Profile + Marketing Website

Website bersifat publik dan dapat diakses tanpa login.

Fokus utama:

Brand awareness
Informasi layanan
Informasi lokasi
Promosi
SEO
Local SEO
Lead generation melalui WhatsApp

Website bukan aplikasi booking pada versi MVP.

1.3 Business Background

Dian Mustika merupakan brand yang bergerak pada bidang perawatan tubuh dan kecantikan, dengan berbagai layanan perawatan untuk pelanggan.

Website dibutuhkan sebagai pusat informasi resmi yang dapat memberikan informasi yang lebih profesional, terstruktur, mudah ditemukan melalui Google, serta membantu calon pelanggan memahami layanan Dian Mustika sebelum menghubungi customer service.

Saat ini informasi bisnis dapat tersebar di berbagai channel seperti media sosial dan WhatsApp. Website akan berfungsi sebagai central information hub.

Konsep:

Google / Social Media
        ↓
Website Dian Mustika
        ↓
Informasi layanan
        ↓
Kepercayaan calon pelanggan
        ↓
WhatsApp
        ↓
Customer Service
1.4 Problem Statement

Website harus menyelesaikan beberapa masalah utama:

Problem 1 — Informasi layanan

Calon pelanggan membutuhkan informasi mengenai:

Problem 2 — Brand credibility

Website harus memberikan kesan:

Problem 3 — Search visibility

Calon pelanggan yang mencari layanan melalui Google harus mempunyai kesempatan menemukan Dian Mustika.

Contoh intent pencarian:

perawatan wanita
slimming

perawatan pasca melahirkan
spa Bintaro
slimming Bintaro

Keyword aktual akan ditentukan melalui tahap SEO research berikutnya.

Problem 4 — Conversion

Website tidak hanya memberikan informasi.

Website harus mendorong pengunjung untuk melakukan tindakan:

Hubungi Dian Mustika melalui WhatsApp.

4.5 Route Naming

Semua route harus menggunakan named routes.

Contoh:

Route::get('/', HomeController::class)->name('home');

Route::get('/tentang-kami', ...)->name('about');

Route::get('/layanan', ...)->name('services.index');

Route::get('/layanan/{service:slug}', ...)
    ->name('services.show');

Route::get('/artikel', ...)
    ->name('articles.index');

Route::get('/artikel/{article:slug}', ...)
    ->name('articles.show');

Route::get('/lokasi/{location:slug}', ...)
    ->name('locations.show');

Blade tidak boleh melakukan hard-code URL:

<a href="/layanan/slimming">

Gunakan:

<a href="{{ route('services.show', $service) }}">
4.6 Route Model Binding

Gunakan slug-based route model binding untuk konten public.

Contoh:

/lokasi/bintaro

Bukan:

/layanan/12
/artikel/25

Hal ini penting untuk:

SEO
readability
maintainability
4.7 Controller Architecture

Controller harus tipis.

Contoh:

class ServiceController
{
    public function index()
    {
        $services = Service::published()
            ->with('category')
            ->latest()
            ->paginate(12);

        return view('pages.services.index', compact('services'));
    }

    public function show(Service $service)
    {
        abort_unless($service->is_published, 404);

        return view('pages.services.show', compact('service'));
    }
}

Controller tidak boleh menjadi tempat menampung business logic panjang.

4.8 Service Layer

4.10 Published Scope

Konten public hanya boleh menampilkan konten yang published.

Contoh:

public function scopePublished($query)
{
    return $query
        ->where('is_published', true)
        ->where(function ($query) {
            $query->whereNull('published_at')
                  ->orWhere('published_at', '<=', now());
        });
}

Kemudian:

Service::published()->get();

5.36 Database Design Principles for OpenCode

AI Agent wajib mengikuti:

Jangan membuat tabel baru tanpa requirement.
Jangan membuat kolom duplicate.
Gunakan foreign key.
Gunakan index untuk field pencarian penting.
Gunakan slug untuk public content.
Gunakan timestamps.
Gunakan soft delete hanya jika diperlukan.
Gunakan Eloquent relationships.
Hindari raw SQL jika Eloquent/query builder cukup.
Jangan membuat repository layer tanpa kebutuhan.
Migration harus reversible.
Seeder harus idempotent atau aman dijalankan ulang dalam development.
